## Core principles
- **Preserve the gameplay fantasy:** never collapse two fun experiences just because they may share code.
- **Player action over architecture:** each experience needs a concrete thing to *do*, observe and enjoy, independent of NPC dialogue quality.
- **Dream vs first fun slice:** an idea may be feasible at some fidelity without its original ambitious form; record that distinction instead of quietly reducing scope.
- **Don't mistake aspiration for feasibility:** GTA V Enhanced limits, standalone constraints, existing mods, costs and performance need research, not guesses.
- **Evidence tiers stay separate:** design idea, source code exists, offline test, installed build and verified GTA result are not interchangeable.
- **Astra is for breakthroughs, not ordinary bug fixing:** give it researched unsolved capability problems only after current capabilities and alternatives are investigated.
- **Source authority:** latest `main` and actual code/tests take precedence over older roadmap text; consult [main roadmap](../ROADMAP.md), [contracts](../research/system-contract-register.md), and [implementation status](../IMPLEMENTATION-STATUS-20261017.md).
- **Not yet decided:** delivery order, which ideas to build, implementation language, plugin/native approach, performance budgets, project timelines and final program boundaries.

## Phase 1 completion criterion
All 28 experiences have: a vivid player moment; ambitious version; minimum genuinely enjoyable playable slice; one distinct capability that must survive consolidation; and a testable, experience-level acceptance question. Then review/edit them with the player before technical feasibility gates. This file set supplies a **first draft**, not sign-off.
