# Phase 4 — standalone audio: production PCM TTS and bounded native queue

**Branch:** `feature/standalone-phase4-audio-escrow`, PR #44 stacked on Phase 3 PR #43. **NOT installed in GTA, NOT physically audible, and NO Essential loaded in standalone source.** The current Essential-based installation and `main` are untouched.

## Implemented

1. **Exact audio authority.** Only a native-confirmed, staged, physically current `NativeTurnPermit` can open a separate `LeaseKind.Audio`. Every IPC write validates host run, world epoch, connection, actor incarnation, conversation turn, audio lease ID, generation, and strict sequence. Node cannot mint an actor or audio owner.
2. **24 kHz raw PCM16LE mono** frames use canonical Base64 over the existing bounded local pipe. Up to 3,000 bytes per chunk, **480 chunks / 1,440,000 total bytes (30 seconds)** per stream, at most four live streams. Every chunk index and exact total byte count must match.
3. **Rolling output queue.** A stream may send up to 30 seconds while **only 192,000 bytes / 4 seconds per stream** are waiting in native memory. Only `IAudioOutput.TryPush` acceptance, on the owner fiber with the exact audio lease rechecked, releases these credits. A null/unaccepted physical sink cannot drain or silently discard audio. `audio.status` reports `queuedBytes, acceptedBytes, forwardedBytes, creditsBytes, sealed`. These are queue/acceptance counters, **not physical played-byte counters**.
4. **Interrupt and backpressure.** Unknown/replayed/out-of-order packets fail. Explicit backpressure can be retried at the same index only after confirmed rejection, bounded by a 2.2-second credit wait; unknown timeouts or disconnect do **not** replay audio. Abort/cancel, native actor recycling, world reset or transport retirement releases buffers/leases. No durable audio files or user speech logs.
5. **OpenAI TTS production adapter**, independent of Essential: `createSpeechPcmProvider` sends `POST /v1/audio/speech` with `response_format: "pcm"`, configured model/voice, and streams raw binary frames. `stageNativePcmStream` preserves even PCM16 samples across arbitrarily split HTTP chunks without materializing the full TTS output. A finite deadline, abort and 30-second audio budget apply. API credentials are read only from the local environment.
6. **Optional typed dialogue → speech**: once an independently produced AI text reply is staged, the standalone `service.mjs` may invoke the PCM speech provider and pass bytes to the native host. Successful result is **`pcm_sealed_not_played`**, not conversation history completion. Without TTS opt-in, existing typed conversations remain text-only.

## Phase 4 S2 — early validated model speech segments (**source implementation, not GTA-playable**)

- `LSA_STANDALONE_EARLY_SPEECH=enabled` is the **explicit opt-in**, requiring both typed Luna and configured TTS. The old complete-response `turn.reply` → `audio.open/chunk/end` remains the default and cannot be mixed with segment mode in the same native turn.
- Independent `streamingResponses.mjs` reads Responses API `stream:true` SSE. It accepts only validated `response.output_text.delta` from the assistant, with a required successful `response.completed` terminator; unexpected tool calls, refusals, malformed/incomplete events, empty/oversized or unbounded text fail closed. Structured actions/tools are not forwarded as audio. Speaker text is split at bounded complete clauses, **before Luna must finish the overall answer**.
- New native owner-fiber IPC commands `turn.segment` (exact ordered source text), `turn.segments.end` (authoritative final segment count) and `audio.segment` (cumulative native-accepted PCM boundary). Up to 12 segments, 500 characters each, 2048 total. Original native actor, turn, session, lease, world epoch and transport identity remain in force; duplicates, wrong segment ordinal, mixed old/new reply modes and post-final text are rejected.
- `segmentPipeline.mjs` starts Qwen/OpenAI TTS as soon as the first segment is validated and native-admitted. **One native audio stream per conversation turn** carries ordered PCM from every segment, with exact segment boundary acknowledgments and an existing 4-second native rolling queue. Native `audio.end` is permitted only after `turn.segments.end` and every PCM boundary. Failure cancels both the audio stream and the exact native turn; no partial/never-played assistant message becomes durable history.
- This is **sequential synthesis**, not concurrent inference jobs. Luna's remote generation can progress while Qwen produces the first segment, but network/provider buffering, voice warmup, the 25-second model HTTP deadline and the interim 2.2-second native queue-credit watchdog still affect actual latency. Later S3/S4 tests must measure cold/warm TTS and replace synthetic-latency assumptions with real device progress.
- The standalone host **still supplies no GTA audio output backend**. No real NPC speech starts; `segment_staged_not_played`, `segment_audio_buffered_not_played`, `segments_final_not_played`, and `sealed_not_played` are explicitly **not physical playback receipts**. Per-segment lip-sync/history and physical completion remain S3 acceptance gates.
- Tests include Node SSE partial frames/finalization, early TTS-before-model-final, streaming cancellation and invalid tool output; C# native segment/lease/PCM marker rejection, ABA and duplicate EOS; and Windows net481↔Node with a local SSE Luna-compatible endpoint that **does not send its model final until first Qwen-compatible TTS HTTP response**, validating genuine early-start behavior offline without API credentials/GTA.

### Safe opt-in for future isolated standalone profile

Keep `LSA_STANDALONE_TYPED_MODE=enabled` and `LSA_STANDALONE_TTS_MODE=enabled`; choose either OpenAI or Qwen via the existing provider-neutral TTS configuration. Add `LSA_STANDALONE_EARLY_SPEECH=enabled` to use S2. Leave it unset to preserve the existing one-shot typed reply path. **Do not enable this as an active GTA replacement while physical actor adoption/output remains disabled.**

## Phase 4 S1 — provider-neutral OpenAI / Faster Qwen3-TTS (implemented in source; GTA not tested)

- The new `speechContract.mjs` validates `pcm_s16le_mono_24000` provider capabilities, profiles, and deterministic per-actor voice routing. `service.mjs` now selects OpenAI or local Qwen via `createConfiguredSpeechRouter` without changing native PCM leases.
- `qwenSpeechProvider.mjs` adapts the independently authored local sidecar from PR #39. Only literal loopback IP endpoints are permitted, with registered voice IDs, strict 24-kHz sample-rate header, 30-second PCM budget, deadlines/cancellation, and **no OpenAI credentials ever sent to Qwen**.
- `tools/qwen/lsa_qwen_server.py` and `voices.example.json` are included independently in the standalone companion. The sidecar offers registered cloned voices, CustomVoice speakers, and VoiceDesign, with one resident GPU model family at a time. Real Qwen models/voice references are **not** included or executed in CI.
- OpenAI TTS accepts provider-neutral per-request voice/instruction overrides; no provider controls NPC identity or claims audible playback.
- `voice-assignments.example.json` illustrates the versioned `worldProfileId + characterId` persistent assignment schema. **Production does NOT yet apply promoted-character assignments:** an exact native character-to-actor binding resolver is required before using them. No name/Ped-handle guessing or spoofable Node identity is allowed. In the meantime, a configured optional voice pool assigns a deterministic voice **for one actor incarnation**, not permanently.
- Tests exercise OpenAI/Qwen provider swapping, local credential isolation, cancellation, invalid voices, forged binding rejection, PCM/sample boundaries and an actual separate native↔Node↔local Qwen HTTP fixture. This is offline evidence, not tested spatial audio.

### Isolated local configuration (not a GTA deployment instruction)

For Qwen synthesis set `LSA_STANDALONE_TTS_MODE=enabled`, `LSA_STANDALONE_TTS_PROVIDER=faster-qwen3-tts`, `LSA_STANDALONE_TTS_VOICE=nathan`, `LSA_STANDALONE_QWEN_VOICES=nathan,aiden_local`, and optionally `LSA_STANDALONE_QWEN_URL=http://127.0.0.1:8000/v1`. The voice IDs must exist in the private sidecar `voices.json`. Optional `LSA_STANDALONE_TTS_SESSION_VOICES` chooses a subset for ephemeral NPC voice variation. These Qwen TTS calls use **no OpenAI TTS credentials**, although Luna reasoning separately requires its configured API credentials.

For OpenAI TTS the default `LSA_STANDALONE_TTS_PROVIDER=openai` uses `OPENAI_API_KEY`, `LSA_STANDALONE_TTS_MODEL`, and `LSA_STANDALONE_TTS_VOICE`. Optional `LSA_STANDALONE_VOICE_ASSIGNMENTS` loads a private versioned file, but is inert for persistent identities until native binding is proven. Private registries and clone recordings are gitignored.

To run the *already installed* Qwen Python environment locally: `python lsa-standalone-companion/tools/qwen/lsa_qwen_server.py --voices lsa-standalone-companion/tools/qwen/voices.json --port 8000 --device cuda`. Model weights, local voices, and the suitable Python environment must be installed separately; no automatic downloads or live calls were performed.

## Verified offline

- Core safety and rolling-queue simulation: exact lease, wrong actor, audio-before-staged denial, stale/reordered PCM, byte alignment, duplicate EOS, queue full with no sink, drain credits only when a **simulated test sink** accepts bytes, 13.75-second PCM transfer under a 4-second native memory budget, cancellation and actor ABA.
- Node tests: production speech request shape, raw HTTP response streaming, odd frame boundaries, bounded total bytes, error and abort paths, explicit backpressure retries and verified `sealed_not_played` without history mutation.
- Windows CI builds net481 native plugin against the public RPH SDK and executes a separate .NET Framework native process ↔ Node stream, including a loopback HTTP TTS provider with the production speech adapter. **No real OpenAI call or in-game device is used.**

## Remaining Phase 4 requirements and safety gates

- **Actual RAGE-targeted output backend:** route stream PCM to the correct NPC through a verified real audio device with spatial position, occlusion/attenuation if applicable, speaker association, and safe concurrent arbitration. Production host currently constructs `NativeAudioRegistry` with **no** `IAudioOutput`. This is intentional; a long stream then stalls after four seconds and fails closed.
- **Physical callback receipts:** distinguish device accepted, audible playback started, interrupted and physically completed before allowing any `PendingDialogue`/character history commit. Neither native FIFO acceptance nor EOS alone can assert speech completion. Device-backed lip sync remains unimplemented.
- **GTA acceptance:** validate installed RAGE SDK, actual plugin fibers and native DECOR actor lifetime/reuse under live GTA Enhanced conditions. The standalone actor adoption gate remains `allowExperimentalAdoption=false`.
- **No rollout, merge or playable replacement claim.** Phase 4 audio pipeline is source-integrated and offline tested only.

The [OpenAI Audio API reference](https://platform.openai.com/docs/api-reference/audio) documents the speech endpoint and raw PCM response format; actual output sample conventions/device routing must still be validated with real output in game.

## S3 first implementation: opt-in device-backed playback (2026-10-11)

**Implementation branch:** `feature/standalone-s3-waveout-playback`, stacked on the draft Phase 4 PR #44. **Not merged or GTA-accepted.** An explicitly enabled `LSA_STANDALONE_AUDIO_OUTPUT=waveout_experimental` selects a per-speaker Windows waveOut stereo PCM backend; no environment flag means the existing null output and truthful backpressure remain unchanged.

- Native owner fiber validates the exact current actor audio lease before every waveOut effect. At most four active voice handles, up to one second of stereo PCM pending per handle, and the existing 4-second native queue / 30-second total cap. Each accepted PCM chunk is downmixed into bounded listener-relative distance attenuation + stereo pan, sourced from the verified actor and local player's RPH positions. **This is an approximate output spatializer, not GTA native audio bus / occlusion / HRTF / vehicle routing.**
- Device-reported source-byte playback progress is distinct from native buffered / forwarded bytes. `audio.end` remains `sealed_not_played`. After exact source EOS, an additive `audio.playback` request can return device-accepted/started/completed/failed and a playback-timed 20ms PCM loudness envelope. Invalid actor/lease, completion before EOS, inconsistent device bytes and retired actor ABA cannot produce a completion receipt. The envelope is **NOT** yet GTA facial animation.
- Producers now use forward-progress based, bounded credit stall detection (6.5 seconds without device forwarding, 90 seconds maximum credit wait) rather than the earlier 2.2-second per-chunk deadline. Device resets, interruptions and transport disconnects fail closed; they never replay a write whose outcome is unknown.
- Added offline simulated physical receipt and replaced-actor tests; real Windows device output, stereo balance, character-binding and a **real NPC's mouth** require a subsequent dedicated GTA acceptance step. Device driver play position cannot prove that a listener heard the words.
- Phase 4 still does **not** provide an automatic speech-history completion writer. Only a future turn-bound listener for these receipts may commit the precise completed segments, or mark partially interrupted speech according to an explicit policy.
- The standalone RageActorResolver deliberately remains `allowExperimentalAdoption=false`. Do not enable it based solely on an offline CI pass; prove the physical actor-cookie/lifetime gate in an isolated Essential-disabled GTA profile first.

## S3 continuation — segment-completion ledger and exact device acknowledgment

**Implemented on S3 PR #48 (stacked, draft, not GTA-accepted):**

- Native `audio.segment` markers now retain a bounded monotonic cumulative-PCM boundary per validated Luna sentence. `audio.playback` exposes `completedSegments`, `markedSegments` and `finalSegments` derived exclusively from device-reported play position and native PCM segment markers. This distinguishes **first sentence finished / second sentence interrupted** from a completed reply. Monotonic playback byte/count regression is rejected. A full `playback_completed` requires native EOS, exact forwarded byte total, finished segment count and terminal device state.
- `audio.playback.ack` is a one-shot exact actor+turn+audio lease acknowledgment, allowed **only after verified whole-stream device completion**. It releases the native audio device handle and invalidates replayable stream receipts. It deliberately does **not** write or expose NPC history.
- Optional standalone Node `LSA_STANDALONE_PLAYBACK_CONFIRM=enabled`, combined with `LSA_STANDALONE_AUDIO_OUTPUT=waveout_experimental` and configured TTS, waits for actual native device completion after `audio.end` for **both** legacy whole-answer and early Luna segment modes. The original `sealed_not_played` status remains distinguishable and no completion is invented without the optional device. At most 6.5 seconds of no playback progress and 35 seconds of completion wait; cancellation / driver failure abort without commit. A physically completed reply emits a **non-content** `physical_playback_completed_no_history` diagnostic; progressing segments report counts only, never transcript text.
- Windows WinMM position sampling requests per-channel samples, validates driver-reported alternative time units, and clamps to transmitted bytes. A driver-position receipt remains a driver-level observation, **not microphone-observed audibility**. `WaveOutSpatialOutput` is a legacy-API proof-of-concept: Microsoft recommends WASAPI/Audio Graphs for new production Windows audio paths. Evaluate replacing it before treating S3 as production quality.
- New Node tests cover two-segment progress, premature completion attempts, regression, driver failure, timeout, cancellation, full-answer and early-stream modes. Native simulated tests cover partially played second segments, premature EOS/replay, same-address actor ABA and exact one-shot acknowledgment. Windows SDK compilation and real net481 named-pipe regression suite run in the same workflow.

**Still open in S3:** actual GTA/Windows device audible integration, proof that each native mouth animation is attached to the correct NPC and does not override combat or ambient faces, true lip/mouth motion (currently only an energy envelope), dynamic indoor/vehicle acoustics and 3D occlusion, an explicit played-only dialogue history commit/partial interruption policy, safe lease renewal for the longest TTS+playback sequences, latency/driver reset soak and multi-NPC spatial acceptance. The native actor-adoption gate deliberately remains **disabled** pending live proof. This PR does not install or enable gameplay features.

**New cross-process S3 fixture:** The Windows CI job now starts the actual net481 named-pipe host, has Node stage two exact audio segments over the production protocol, and verifies `audio.playback` plus single-use `audio.playback.ack`. This fixture uses an explicitly **synthetic** completion-reporting `FixtureOutput`; it proves packet/schema/device-ledger wiring only, not sound-device operation or GTA acoustics.
 
## S3 continuation — optional native GTA speech-mouth presentation (2026-10-11)

**Experimental source implemented on PR #48, not GTA validated.** The independent host now optionally constructs `RageLipSyncPresenter` when **both** `LSA_STANDALONE_AUDIO_OUTPUT=waveout_experimental` and `LSA_STANDALONE_LIPSYNC=facial_experimental` are set. Default stays **off**. `LSA_STANDALONE_PLAYBACK_CONFIRM=enabled` remains an independent Node option for verified completion, not a requirement for visual cues.

- `NativeAudioRegistry.PumpLipSyncOnOwner` runs on the RPH owner game fiber with bounded four-actor work. It validates the current physical output, exact actor/turn/audio lease, monotonically advancing device playback position and non-silent 20-ms source-PCM envelope before considering any visual effect. Buffered TTS, device acceptance without playback, stalled/regressed device position and completed/failed streams cannot drive mouth cues. This is *not* a network-driven or guessed audio timer.
- `RageLipSyncPresenter` revalidates the native lease and DECOR-backed actor incarnation immediately before the game native call, never executes from Node/IPC threads, refuses player/invalid/dead actors, and yields during combat, shooting, falling and ragdoll. It requests the fixed `mp_facial` animation dictionary on its owner fiber and does not call the facial clip unless GTA reports that dictionary loaded. At most one `PLAY_FACIAL_ANIM(ped, "mic_chatter", "mp_facial")` cue per 240 ms per exact stream. It does not clear facial idle overrides or issue body tasks and simply forgets its bookkeeping when the stream retires. **This is a GTA speaking-mouth gesture; it is not phoneme/viseme-accurate facial animation, and exact in-game clip behavior remains unverified.**
- Energy now follows the original device-accepted mono PCM instead of volume after listener-distance attenuation, so NPC mouth movement is not erroneously suppressed just because the player is far away. The device *playback sample clock* remains the only gate for when that energy can cue an animation.
- Offline core tests verify default/null safety, rejected faux-sink facial adapter, queue-before-playback, device-accepted-before-playback, advancing sample/energy cues, silence/stall/regression rejection, recycled handle ABA suppression, and cleanup with no game-world facial reset. The Windows CI host builds with the real published RPH reference, but **no test plays a game facial animation**.
- Native log line reports `actor_adoption=disabled`, `waveout=off|experimental`, `facial=off|experimental` without character or audio content. The physical actor-adoption gate remains `false`; DO NOT enable it or claim deployability from offline tests. An isolated Essential-disabled GTA profile must prove both correct NPC voice routing and facial behavior under interruptions.

**Further S3 gates:** hands-on GTA validation of the specific `mic_chatter` clip and model compatibility, reliable end-of-speech return to natural face without clearing another controller's expression, vehicle/indoor acoustics, tested device reset/error/lease expiry, an intentional completed-only/partial dialogue-history policy, and a production-grade spatial audio/mixer backend. Neither this speech gesture nor WinMM driver position proves the player could hear the words.
