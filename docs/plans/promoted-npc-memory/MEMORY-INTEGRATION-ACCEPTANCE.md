## 3. Non-negotiable architecture review

- **One P2-owned database:** \`P2SqliteProfileStore\` and \`P2SqliteFoundation\` own the durable journal, permanent memories and queue; the new M3 coverage table and M4 projection use that same file/connection. M5's auxiliary \`M5SqliteServices\` currently opens a second connection to the *same file* under the P2 serialized write gate; this needs transaction-lock/deadlock scrutiny and cleanup before activation. No new daemon or mandatory local model.
- **One PS4 frame:** \`knowledgeRenderer.mjs\` remains the sole model-facing \`TurnKnowledgeFrame\` producer. The M4 typed recall contributor exists but is **not yet embedded and revalidated** within its \`RECALLED\` and earlier-conversation allocation, so memory is not available to normal Luna dialogue. Do not introduce a second system prompt or bypass the PS4 byte budget.
- **PS2 is witness authority:** Native candidates, generic GTA signals, PS3 salience, or model inferences must **never** be journaled as facts witnessed by a particular NPC. M3 requires matched promoted owner and correlated PS2 observer receipt. Lack of native participant proof leaves the protagonist \`unknown\`. Negative coverage requires its own certified native receipt.
- **Source/identity/time:** WorldProfileId, TimelineId, CharacterId, native run/epoch/incarnation/encounter, accepted turn and protagonist must be verified again at the actual write and context-send boundaries. Timeline suspension must stop writes, not auto-select a new save.
- **Memory privacy:** M5 tombstones/corrections suppress recall/derived evidence. Before production enablement, the live editor/command authorization surface must prove seven-day trash/restore/purge and source-bound deletion, including export confidentiality.
- **Optional cloud:** M7 is Luna cloud only, off-turn, user-opt-in, with persistent leases, daily/monthly reservations, Retry-After and cancellation. No real Luna calls or real billing receipts were executed in this integration review; do not assume cost limits are proven with live APIs.
- **Priority:** M9 cue-to-Director execution must use existing verified PS6 C-06 entitlement, original stock player speech priority, per-actor cooldown and native authorization. No special memory callback may bypass native Director/player priority.
