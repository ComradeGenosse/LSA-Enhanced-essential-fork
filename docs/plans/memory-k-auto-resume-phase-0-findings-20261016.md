# Memory K single-timeline auto-resume — Phase 0 source investigation

**Completed source inspection:** 2026-10-16  
**Integration baseline:** PR #138 `cb39610698dd10870f3eb35656605a2264177ae4`  
**Status: NO-GO for automatic save identity assertion with current authenticated frame; GO for a separate design of trustworthy save proof.**  
**Change scope:** this report only. No runtime changes, native DLL changes, modifications to #184 or merges.

## Source-verified conclusions

1. **Native C-13 hello does not send a stable save ID.** `native/intelligence/IntelligenceChannel.cs` `Hello()` includes `hostContextVersion:1`, `hostRunId`, `worldEpoch`, plus capability flags and per-channel epoch/stream. These are native session/epoch identity, not persistent GTA save identity.
2. **JavaScript deliberately exposes only that three-field host authority.** `lsa-essential-e1-candidate/src/context/hostContext.mjs` specifies `HOST_FIELDS=['hostContextVersion','hostRunId','worldEpoch']`; `readHostContext()` projects exactly those three keys and `validateHostEnvelope()` enforces the closed extension. There is no `saveId`, save-slot, save-file fingerprint, or authenticated persisted save-lineage identity.
3. **Authenticated intake is live but not proof of same save.** `src/perception/intelligenceClient.mjs` passes parsed pipe frames into `ShadowRuntime.ingest(v,{authenticated:true})`, publishes accepted hello/epoch context, and retires owner proof on source transitions. `src/perception/shadowRuntime.mjs` obtains the context via `readHostContext(v)`. A fresh authenticated host context cannot prove which GTA save was loaded.
4. **Native world reset detection exists but is discontinuity detection.** `native/promoted-characters/PromotedCharactersIntegration.cs` calls `Host.ObserveGameTick`, rotates the channel and retires live associations upon clock discontinuity; `native/intelligence/IntelligenceIntegration.cs` uses `Host.HostRunId` and `Host.WorldEpoch`. Clock regressions/epoch changes can signal some transitions; absence of a regression does **not** prove the same save. `native/promoted-characters/MemoryOwnerAuthority.cs` attests owner/host/run data, not stable save lineage.
5. **SQLite stores a selected timeline, not save identity.** `lsa-shared-brain/src/characters/sqliteFoundation.mjs` defines `timelines(timeline_id,world_profile_id,label,created_at_utc,active)` and a unique active index. `listTimelines()`, `activeTimelineId()`, `activateTimeline()` support explicit timeline choice, without an authenticated GTA save-file discriminator. `world_profile_id` is an application namespace, not evidence that GTA loaded the same save.
6. **Revocation and stale-write protections must remain.** `lsa-shared-brain/src/characters/sqliteProfileStore.mjs` maintains `#authorityGeneration`, `#sourceContext`, `#confirmedSource`, checks current source and generation in the queued writer, and revokes on changed host/epoch. `confirmTimeline` serially activates and stamps confirmed source; it is an existing user-facing confirmation mechanism, not automatic evidence.
7. **Bootstrap order:** `lsa-essential-e1-candidate/src/bootstrap.mjs` initializes SQLite before intelligence, registers `subscribeVerifiedHostContext(context => store.setVerifiedHostContext(context))` and `subscribeWorldBoundary(boundary => store.onBoundary(...))` before starting intelligence. Do not activate memory in the constructor or on raw socket connection.
8. **Important world-epoch callback ordering hazard:** `src/perception/intelligenceClient.mjs` publishes `publishHostContext(next)` on accepted world epoch **before** calling world-boundary listeners. Thus an auto-resume callback listening to host context must not authorize itself before the boundary callback applies its veto. Fix design must defer/serialize decision after the boundary is fully processed (or change dispatch order while preserving existing behavior and coverage). The existing write queue is necessary but not alone sufficient if callback ordering isn't fixed.
9. **Manual fallback:** `src/characters/editorServer.mjs` exposes `timeline_list` and `timeline_confirm` with matching UUID confirmation token. Keep this endpoint. `memoryK` config validator in `src/memory/capabilityPolicy.mjs` presently accepts only `capabilities`, `profile`, and `pauseLearned`; strict opt-in key remains a future implementation.
10. **Affected test surfaces:** `lsa-essential-e1-candidate/tests/memory-k-native-source-only.test.mjs`, `tests/memory/nativeCurrentOwnerAuthenticatedIntake.test.mjs`, `tests/memory/nativeMemoryAuthority.test.mjs`, `tests/memory-capability-policy.test.mjs`, `tests/memory-runtime-composition.test.mjs`, `lsa-shared-brain/tests/memory-k-production-w04-sqlite.test.mjs`, `tests/memory-k-ws4b-durability.test.mjs`, `tests/memory-integrated-storage.test.mjs`, plus H1/H2 and privacy tests. Identified by repository paths; **not run in this read-only investigation**.

## Proof-feasibility verdict

**NO-GO:** With current verified hello/epoch data, accepting the last SQLite active timeline automatically cannot reliably distinguish a genuine same-save relaunch from loading a different save. There is no source-established stable save discriminator in the inspected C-13 host projection, native hello or SQLite timeline row. This is an evidence-based lack of guarantee, not proof that GTA or other native code has no save API.

**Native DLL impact: unresolved, potentially necessary.** A JS-only implementation can be accepted *only if* additional repository inspection establishes an already existing authenticated native save-lineage proof in another suitable frame/channel that carries identity across restarts, and documents how copied/overwritten saves and save resets are handled. Otherwise the solution needs an expressly scoped native source of proof (or a consciously weaker user-trust mode with different acceptance criteria). No DLL is changed by Phase 0.

**Suggested next action:** a narrow native save-discriminator feasibility spike, first determining whether the supported GTA/RPH APIs can deliver a reliable current-save fingerprint or lineage value, including the difference between explicit save slot, copied save, loaded checkpoint and unsaved gameplay. Model and test the proof schema separately before writing auto-resume logic. Do not substitute `hostRunId`, `worldEpoch`, `worldProfileId`, actor identity, game tick, or the fact that one timeline exists.

## Completion limits

Repository source was inspected via connected GitHub at pinned PR #138 head. No GTA installation was used, no SDK/native save APIs were validated by executing GTA, and no tests were run. This completes the **online source-assessment and architectural feasibility gate**, not empirical in-game feasibility. A final Phase 0 sign-off for native save semantics will require verifying the chosen discriminator against actual GTA save/reload behavior; Phase 1 automatic authorization stays blocked pending that proof.
